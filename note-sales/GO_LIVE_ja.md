- 当日の有料買い目と過去実績はモデル・条件が異なる可能性がある。必ず区別する。

## 本番公開の条件
1. 出走と買い目を返せる信頼できる HTTPS の予想供給元を用意し、GitHub Actions の変数 BOAT_AI_FORECAST_URL に /v1/forecasts のURLを登録する。現在のクラウドModel A BUYは十分なライブデータ元がなく停止している。予想を捏造しない。
2. 最も早い対象レースの締切まで記事生成時に45分超、投稿時に30分超あること。既存のT-8/T-5直前情報だけではこの条件を満たさないので、早い時間帯から予測を返す別経路が必要。
3. noteアカウントを用意し、初回有料記事で必要な本人情報の登録をアカウント所有者が済ませる。
4. noteのブラウザ画面で有料エリア設定が想定通り動作することを確認する。https://www.help-note.com/hc/ja/articles/360008882894
5. ログアウト状態で公開済み記事を開いて、購入画面が表示され、有料部分の買い目が見えないことを確認する。
6. GitHub SecretsにNOTE_SESSION_STATE_B64を登録。ログイン情報と同等の機密情報なのでチャットやIssue、リポジトリに貼らない。端末と本人による安全なログインが必要。期限切れたら再ログインする。AndroidのみでPlaywrightブラウザのセッション取り出しは難しいため、PCや適切なクラウドブラウザ環境を使用する。
7. その後でのみGitHub Actionsの変数NOTE_BROWSER_UI_VERIFIED=true、およびNOTE_AUTO_PUBLISH_ENABLED=trueを有効化する。先にNOTE_SALES_ENABLED=trueで生成工程だけ試せる。

## 状態確認

- 環境不足のチェック: python note-sales/preflight.py
- GitHub設定画面: リポジトリ > Settings > Secrets and variables > Actions
- 本番ワークフロー: .github/workflows/note-sales-daily.yml
- 定期起動: 日本時間10:00〜20:30、30分間隔。ただし初期状態はオフ。

## 重複投稿・異常時
公開前にnote-sales/published/YYYY-MM-DD.jsonという公開メタデータのPUBLISHING状態を書き込んで二重投稿を防止。公開後にログアウト閲覧が正常と確認できた場合のみPOSTED_VERIFIEDへ更新。エラーが発生してPUBLISHINGのままなら、noteに記事が存在するか人間が調べてから再開。自動再投稿は禁止。

## 制約
- 一般個人向けの自由に使える公式note投稿APIは未提供。2026年10月開始のnote APIはnote proの対応連携サービス向け。https://note.jp/n/n6e16e4dc9e26
- 現状のブラウザ投稿コードは実アカウント上で未検証。ログイン/二要素認証/本人確認の突破は自動化しない。
- リポジトリは公開のため個人バックアップや有料買い目、認証情報をコミットしない。
