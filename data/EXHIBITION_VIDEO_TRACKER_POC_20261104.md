# 展示映像 AI: 動画ピクセルから5性能指数までのオフライン PoC（2026-11-04）

## 何が動くようになったか

`scripts/exhibition_vision/video_tracker.py` に、**録画済みのローカル動画を実際にデコードし、6艇の位置をフレームごとに追跡する処理**を追加した。動画はFFmpegでメモリへRGBデコードし、映像ファイルや抽出フレームをGitHubにアップロードしない。

1. フレーム中の6色の連結領域を、初期位置から各艇ごとに追跡。艇の対応を推測で入れ替えない。
2. 水面上の座標をカメラの射影変換でmに換算。最低6つの物理座標基準点のうち、**4点で学習・別の2点以上で誤差を検証**。確認点が1mより大きくずれれば停止。
3. `runup / straight / turn / exit` の4つの時間区間で軌跡を分類し、7つの物理測定値を算出。
4. 既存 `kinematics.py` → `scoring.py` に接続し、出足・行き足・伸び足・回り足・ターン性能の **6艇内相対指数(0〜100) / 順位** を出す。
5. 追跡率・色領域信頼度・校正誤差・速度上限・保存時刻の品質検査に落ちたら `UNUSABLE`。成功しても研究専用で、Android予想・BUY/SKIPへの自動反映は**禁止**。

これまでの「外部AIの追跡データを受け取って採点するだけ」から、**実際の動画デコード→暫定的な画像追跡→物理特徴量→採点**まで一段進んだ。ただし検証は**自作の合成6艇動画だけ**で、実際の展示映像・精度の実証は未達。

## 使い方（正当に利用できるローカル動画のみ）

```bash
PYTHONPATH=scripts python3 -m exhibition_vision.video_tracker \
  --video /path/to/allowed-exhibition.mp4 \
  --config /path/to/venue-camera-calibration.json \
  --output /tmp/exhibition-video-shadow.json
```

- Python標準ライブラリとシステムのFFmpegを使用。学習済み物体検出モデルやGPUは不要。
- 入力動画は既に手元にあり、解析・一時保存が認められたもの。公式ライブの隠れたストリームURLを探索したり、保護を回避して動画を落とす処理は入れない。
- 設定JSONの `race` は `date` / `venue` / `number` / `deadline`。 `video` は `source_id` / `permission_reference` / **`recording_completed_at`（最後のフレームを取得し終えた時刻、ISO8601タイムゾーン必須）**。取り込み時に動画SHA256を計算し、検出器/校正版を記録する。
- `tracking` には `width`, `height`, `fps`, `duration_s`, `calibration.id`, `calibration.anchors`（`pixel` と `meters` を6組以上）、`calibration.turn_marker_pixel`, `boats`（1〜6号艇の `lane, rgb, start_px, radius_px, tolerance, min_pixels`）、`phase_windows`（4区間の `phase,start_s,end_s`）を設定する。
- `recording_completed_at` は録画開始時刻ではない。**締切後の1フレームでも含めれば事前予想データとして使ってはいけない。** 収録時刻の自己申告だけでは第三者による検証はできないので、実運用には取得元の時刻証拠が別途必要。

## なぜまだ全国24場のリアルタイム動画AIになっていないか

- **艇の検出:** 現在は1艇1色の単純な追跡。実況テロップ、撮影角度変更、遮蔽、波・反射、ボート同士の重なりに強い学習済み detector は未実装。艇番号・進入コースと色の恒常対応も未検証。
- **時系列の区間判定:** `phase_windows` は録画に合わせた4区間の指定が必要。実映像からターン開始/終了を自動認識するモデルは未実装。
- **実測の較正:** 実会場の地上距離と6以上の対照点が必要。画像ピクセルをmと偽ることは禁じる。
- **自動動画取得:** BOATCASTは無料視聴を案内しているが、自動取得に利用できる許可済み直接動画APIが確認できていない。無断ダウンロードや連続再配布は行わない。**問い合わせはしない**というユーザー方針を維持する。
- **締切8分前:** Android v0.18.23がその時点で取得するのは公式等の公開**数値**であり、動画指標はまだ統合されない。
- **研究証拠:** 合成動画テストに合格しても、実レースの評価件数・予測精度改善・ROI改善はゼロ件のまま。2025年10〜12月Q4ホールドアウトとModel Aの既存パラメータは触らない。

## 次に実行する工程

1. 1会場の正当に利用できる展示動画を数十件用意し、同一画角の6艇が見える区間を特定（現状、実動画は未取得）。
2. テロップ遮断・カメラ切替検出・水面マスクと、艇用検出器（色のみに依存しない）を実動画で試験する。
3. 人手の位置ラベルとモデル出力の誤差・艇取り違え率・追跡率を集計。カメラの距離基準を独立点で確認する。
4. 映像5指数を独立の先行特徴として保存し、Model Aとの前向き比較ゲートを通過するまでは予想に混ぜない。

## テスト

```bash
PYTHONPATH=scripts python3 -m unittest discover -s scripts/exhibition_vision -p 'test_*.py' -v
```

6艇の色・位置合成動画をFFmpegで可逆動画としてエンコードして、実際のFFmpegデコード・追跡・5指数生成を検証する。基準点の虚偽校正、6号艇欠損、色の重複、フレーム破損はエラーにする。
