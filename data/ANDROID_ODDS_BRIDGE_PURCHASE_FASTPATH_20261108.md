# 2026-11-08 — 既存Androidオッズ再利用・購入機能の最短導入ルート（研究用）

## 現在地を明確に分離

- Androidは既存の公式3連単オッズ取得・端末内監査（`LiveOddsAuditRegistry`、`OddsFetchResult`、`TrifectaOddsLocator`）を保持。今回この取得機能を消去・作り直さない。
- 既存 `CollectorHeartbeatUploader` がクラウドへ送るのは**件数と端末受信時刻のみ**。120オッズ値、提供元の原観測時刻、出走展示6艇はまだ送っていない。送信成功はクラウド予想の認証済みデータ取得を意味しない。
- Android購入関連（公式アプリへの画面操作エンジン、1号機→2号機承認付き購入指示、受領確認）はPR #69からmainへマージ済み。署名APK **v0.18.31** はGitHub Releasesに存在する。ただし実機での公式画面対応表は未校正で、**実購入成功は0件（未検証）**。このPRはAPK/本番Workerを変更しない。
- Cloudflareの予想Cronは独立した許諾済みソースと認証済み履歴を必要とする。**端末から取得できる**ことを**サーバー再配信の利用許可**やソース時刻の真正性として扱わない。

## 今回実装したもの

`scripts/android_odds_bridge_preflight.mjs` とオフラインNodeテスト、専用CIを新規追加。将来のAndroid→サーバー間プライベートブリッジの入力契約を先に固定する。

- 当日JSTの日付/場番号1〜24/レース番号1〜12/締切時刻の一致を検証。
- 3連単の**120種類の組番を重複なし・不足なし**で要求し、数値以外・非正数・余計なフィールドを拒否。認証情報や購入情報を運ばない。
- Androidが受け取った時刻とサーバーが受け取った時刻を区別。最大2分の端末遅延を許容するが、締切後到着・未来時計・古い時計を拒否。
- ソースの元観測時刻は `null` を許容し、端末受信時刻で**捏造して埋めない**。端末から自己申告された元観測時刻は、時刻差を通っても**独立検証済み**にはならない。
- T-8/T-5の時間窓を識別するが**推奨BUY/SKIPには一切接続しない**。合格状態は常に `DEVICE_ODDS_QUARANTINED`、`eligible_for_forecast=false`、`eligible_for_buy=false`。
- ネットワークアクセス/D1/Android起動/投票処理はなし。合成データのみのテスト。実際の120オッズをGitHubのログやArtifactsに保存しない。

## 既存機能を利用する実装順（最短）

1. **既存Android取得経路の調査**：`OddsFetchResult` の120件のスナップショットを、値・組番・元サイトの表示時刻と端末受信時刻に分けて確認（秘密情報、購入履歴、再ログイン情報を収集しない）。実機で正規に閲覧する範囲を超えてアクセスしない。
2. **利用権・端末外共有の確認**：公式サイト/公式アプリのコンテンツをクラウドへ送る条件を独立に確認。個人閲覧で取得できることと、外部サーバーへの自動再送信は異なる。許諾未確認なら端末内オフラインでのみ監査。
3. **private transport**：利用条件が整理できた場合のみ、既存Keystore暗号化・Bearer認証を利用した**新しい限定POST**を独立PRで実装。既存 `/heartbeat` は厳密な12フィールド契約なのでオッズを追加せず別経路とする。回数制限/当日/サイズ上限/端末内明示的opt-in/保存期間制限/トークン漏えいなしを必須にする。
4. **ライブ認証は別ゲート**：120値とT-8/T-5の受信確認ができても、取得元が原観測時刻を証明できない場合は `UNAVAILABLE` のまま。Model A履歴・6艇展示と照合し、端末とクラウドの同一実レースで照合してから有効化を審査する。

## 購入機能の導入を優先する順番

- **すでに存在**：v0.18.31の配布、1号機での明示的な購入指示（買い目・金額の確認、60秒以内の承認）、2号機での受信、公式アプリの既存タスクを前面へ戻す処理、期限/上限/組番のゲート、誤送信防止、公式受付番号・成立金額の突合コード。
- **実機導入の本当のブロッカー**：Androidの公式BOAT RACEアプリの、選場→レース→3連単→艇番→金額→ベットリスト→最終確認→投票→受付明細、各画面の**正しいリソースID/表示ラベルの対応表が未取得**。WebViewがAccessibilityに現れない場合、推測した座標をタップする実装はしない。ログイン切れの場合は本人の手動ログインが必要。公式サービスの自動操作利用条件も要確認。
- **最短の受入手順**：2号機だけv0.18.31を既存データのまま上書き更新 → 設定でユーザー補助を許可 → 公式アプリを手動ログイン → BOAT AIの診断で静的ID・見出しだけをローカル収集 → 個人情報を伏せた画面対応表でデータインポート → **購入確定を行わないドライラン**で全画面・最終金額を確認 → 公式利用条件の確認・購入履歴との一貫性試験を経たうえで当該1回の明示承認に限定して実購入を検証。ID/パスワード/承認番号はチャット/GitHubへ渡さない。
- クラウドWorkerへschema v2がデプロイされたか、実際の2台の共有キーが一致するか、本番端末で未確認。通常の買い目転送は購入実行指示ではない。表示上「購入開始」があっても、公式画面プロファイル未校正なら自動投票はできない。
- **失敗時の安全条件**：締切2分以内・合計5,000円超・ログイン切れ・別レース・余分なベット・画面不一致・受付結果不明 → 停止。投票操作直後に成功不明の場合は再試行しない。電話投票履歴を手動確認する。

## 次の一手と境界

この研究PRでできたのは入力の**オフライン検査**であり、Android本体からのオッズ送信・許諾確認・本番BUY/実購入実証ではない。次はオッズ実取得時にデバイスに何が残るかの形式照合、および**購入の公式実画面プロファイル取得とドライラン**を最優先。技術的に未確認な画面を擬似的に埋めない。実レースでの投票や課金は自動実行しない。

## 2026-11-08 17:38 JST — 実装前進（既存 `OddsFetchResult` の安全な検査）
