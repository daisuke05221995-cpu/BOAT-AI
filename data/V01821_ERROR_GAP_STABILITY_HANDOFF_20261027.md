# BOAT AI v0.18.21 データ欠損・障害診断 引継ぎ

## 背景

ユーザー実機で2026-10-27に反復エラーが発生し、その後表示が消えた。v0.18.20で直前オッズのジョブ競合は改善したが、開催時間外では実機再現できない。発生原因を特定したと断言しない。

## 変更

1. `fetchProgramJson` で受信直後にキャッシュ保存するのをやめ、`BoatRaceJsonParser` で日付照合済み・1レース以上のデータだけを保存する。`today.json` が前日を返した場合、当日キャッシュの上書きを防ぐ。
2. `BoatViewModel.loadDate` の待機応答が同日表示済みデータを消すのを防ぐ。新しい予想・損益履歴の生成も空データでは実行しない。
3. `AtomicFile` で開催データの書込みを原子的にし、書込み途中障害でも旧データを守る。
4. `DataFetchAuditStore` の最大48イベントのリング履歴を追加（開催データ、詳細オッズ、自動オッズ、成功/待機/警告/失敗、端末時刻、アプリ版、240文字以内の詳細）。外部送信なし。JSONバックアップには `dataFetchAudit`、`lastCrash`、`lastBackgroundFailure`、`lastBackgroundFailureAt` を追加し、従来の `schemaVersion: 1` 互換を維持する。
5. バックアップには実購入、端末・クラッシュ情報が含まれるため、公開場所へアップロードしないよう画面に明記する。

## テスト/制限

- `ProgramDataAvailabilityTest`: 404待ち、前日データ混入、空データでのキャッシュ保護、同日画面維持。
- `DataFetchAuditWindowTest`: 保存上限48件、順序、失敗記録保持。
- Android CI: unit/lint/Debug APK → signed Release APK の順に確認。
- 実機通信と結果補完の成否は、次に開催されるレースで確認する。公式オッズが失敗した際に架空の値を作らない購入安全基準は維持。

## 次回実機確認

1. アプリを削除せず v0.18.21 に更新し、前版の購入・予想・損益が残ることを確認。
2. レース開催中の30分以内・展示済み対象で自動オッズの試行数と成功・失敗数を確認。
3. 数分利用後、`BOAT-AI-backup.json` を非公開で共有し、`dataFetchAudit` の失敗元、端末障害、期間欠損を別々に検証。
4. 旧 343 BUY 監査と新バージョンの追跡期間を混ぜない。360R達成やROI改善を未確認のまま主張しない。
