# BOAT AI 展示動画PoC 継続研究：カメラ切替検出・旋回区間自動推定（2026-11-06）

## 実装

- `scripts/exhibition_vision/video_tracker.py` に、フレーム間の広範囲な画素変化を検出して**突然のカメラ切替を停止条件**にする処理を追加。単一カメラ用のメートル較正が映像切替後にも適用される誤計算を防ぐ。ただし**低速パン・ズーム・徐々の画角変更をすべて検出できるわけではない**。
- `scripts/exhibition_vision/phase_detection.py` を追加。**同一カメラで同時に追跡できた6艇の進行方向変化**から、1回の大きなターンを仮検出する。6艇の中央値と時間平滑化を利用する。
- ユーザー指定の `tracking.phase_mode: "auto_turn_v1"` では、従来必須だった `phase_windows` の手入力を省略できる。候補ターンの前後を `runup / straight / turn / exit` に仮分類し、既存 `kinematics.py` の7測定値・`scoring.py` の5項目指数へ渡す。
- 観測艇が6艇揃わない、ターン変化が小さい、複数ターンが混在する、開始/終了のフレームが足りない場合は**失敗させる**。画角切替も不合格。
- 自動検出の `runup` と `straight` の境界は**ターン前フレームの半分**という暫定ヒューリスティック。現実のピット離れ/進入/助走の意味まで推定できていない。研究結果には `phase_detection.runup_split_is_heuristic=true` を記録する。

## 実験条件と結果

- 正常：合成6艇が直線→約90度旋回→直線の軌道。6艇中央値からターンを検出、全4フェーズにラベル付け、5指数まで計算。
- 正常：1艇につき一部フレーム欠損があっても、観測した座標のみ使い、架空のフレームを補間しない。
- 異常：直線だけの映像で存在しないターンを作らない。
- 異常：2箇所の大きなターンがある動画で恣意的に1つだけを選ばない。
- 異常：画面全体の急な色変化はカメラ切替として拒否。
- FFmpegで合成した可逆動画を実際にデコードするE2Eテストを含め**全62テスト成功**。

**重要:** 実際のボートレース展示映像をこの評価に使っていない。したがって6艇識別率、実メートル誤差、ターン区間の正確さ、締切8分前の完成率、予測精度、回収率の実測改善は**未検証**。

## 使い方

先行PoC `data/EXHIBITION_VIDEO_TRACKER_POC_20261104.md` の設定で、`tracking` から `phase_windows` を除去して次を追加する。

```json
{
  "tracking": {
    "phase_mode": "auto_turn_v1"
  }
}
```

上記は**差分例**であり、実行時には以前と同じ `width`, `height`, `fps`, `duration_s`, `calibration`（物理座標の6点以上の基準）、`boats`（6艇の最初の色と座標）を指定する。完全無設定の動画を理解するモデルではない。

## 次の実務ゲート

1. 実際の展示リプレイで「1場・1レース」の合法なローカル入力を確保する。自動ダウンロード方法は未確定。問い合わせはしない。
2. 実映像の場面切替、6艇同時遮蔽、テロップ、実際の旋回前後を含む区間をラベル付けし、偽検出率・ターン時間誤差を実測する。
3. 1会場のカメラ位置と観測範囲を特定し、物理的な6基準点を置いて較正する。異なる画角は別カメラIDを要求する。
4. まだ学習済み艇検出器はない。実映像の正解ラベルを得た後に、色・初期位置に頼らないモデルと比較する。
5. Model A/Androidの予想・BUY/SKIP・2025年Q4封印データは変更しない。独立した締切前精度検証に合格するまで完全に研究専用。
