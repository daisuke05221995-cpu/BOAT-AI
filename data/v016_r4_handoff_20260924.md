## ユーザーの最新方針

従来の2023/2024中心の同型検証を繰り返すより、**現在の実運用に近い2025年を主対象にして、新しいCORE BUYモデルを作り直す**方向へ変更する。

特に重視する新仮説:

- 選手ID（登録番号）をキーにした選手個人の過去傾向
- コース別の個人成績
- 展示タイムそのものだけでなく「本人の普段との比較」
- 展示STそのものだけでなく「本人の普段との比較」
- 展示順位 / 1位との差 / 6艇内の相対差
- 進入コース変化
- 1号艇信頼度低下
- モーター / ボート差
- 風・波など当日条件
- 市場オッズは最終選別用。選手ID自体を単純な連続数値として学習させない

ユーザー了承済みの方向:

**「2025年中心・選手ID×コース×展示反応」をr1〜r3とは別仮説として新規研究する。**

## 最重要: r4は既存r1〜r3の閾値再調整ではない

過去の144条件は2024年通年で不採用確定済み。同じ閾値の微調整や同じモデルの焼き直しは禁止。

r4では、選手の個体差と展示反応を新しく時系列特徴量化する。

登録番号はカテゴリ識別子として履歴テーブルを引くキーに使う。`racer_number=5042` のような数値そのものを、そのまま強弱を表す連続値特徴にしない。

## r4で作るべき中心特徴量

### 1. 選手個人の基礎履歴

各レース当日より**前**の結果だけから登録番号ごとに更新する。

候補:

- 過去出走数
- 1着率 / 2着内率 / 3着内率
- コース別出走数 / 1着率 / 3着内率
- 直近30/60/90/180日成績
- 直近N走の重み付き成績
- 平均ST / ST標準偏差
- コース別平均ST
- 平均展示タイム
- コース別平均展示タイム
- 展示順位が上位だった時の1着率/3着内率
- 展示STが本人平均より良かった時の1着率/3着内率
- 展示タイムが本人平均より良かった時の1着率/3着内率
- `course_changed`時の成績

サンプル数が少ない個人値は、全体/級別/コース別平均へshrinkすること。生の少数サンプル率をそのまま使わない。

### 2. 「今日の展示が本人比でどうか」

最重要。

例:

- `exhibition_delta_self = today_exhibition - historical_person_mean`
- `exhibition_z_self`
- `preview_st_delta_self = today_preview_st - historical_person_preview_st_mean`
- `preview_st_z_self`
- 6艇内展示順位
- 6艇内展示ST順位
- ベスト展示との差
- ワースト展示との差
- 1号艇との展示差
- 本人の通常レンジから外れた改善/悪化フラグ

展示タイムは小さいほど速いので符号を明示して実装すること。

### 3. 選手×コース×展示反応

単なる「1コース勝率」ではなく、

- この選手がこのコースに入った時
- さらに展示が本人平均より良い/悪い時

で着順分布がどう変わるかを特徴量化する。

候補:

- `player_course_count`
- `player_course_win_rate`
- `player_course_top3_rate`
- `player_course_fast_preview_count`
- `player_course_fast_preview_win_rate`
- `player_course_fast_preview_top3_rate`
- `player_course_good_st_count`
- `player_course_good_st_win_rate`

十分な件数がなければ、player全体 → course全体 → globalへ階層shrink。

### 4. 1号艇信頼度低下

専用race featureを作る。

候補:

- 1号艇の本人比展示悪化
- 1号艇の展示順位
- 1号艇の展示ST悪化
- 1号艇の1コース個人成績
- 1号艇のモーター差
- 1号艇の全国/当地成績と他艇差
- 1号艇が進入変化したか
- 外艇に「本人比で強い展示反応」が複数いるか

この「1号艇信頼度低下」はCOREのSKIP判定にも使える。

## リーク防止ルール

必須:

- 対象レースの結果をそのレース特徴量生成前に使わない
- **同じ日の全レースの特徴量を作り終えるまで、その日の結果を選手履歴へ反映しない**
- 2025-10-01以降はURL構築前に拒否
- 結果データのactual ST/actual entranceを予測特徴に使わない
- 予測用の進入はpreview `racer_course_number`のみ
- 払戻は評価専用
- オッズは評価/購入選定専用とし、利用時点制約を明記

同日内で午前の結果を午後レースの履歴に反映することも、まずは避ける。日単位walk-forwardの方が監査しやすい。

## 2025中心の研究期間案

2024を主なROI評価年に戻さない。

2024は**選手履歴のseed / 事前学習用**として使ってよい。2025で十分な選手履歴を持たせるために有効。

推奨初期分割:

- history seed: 2024-01-01..2024-12-31
- r4 model train: 2025-01-01..2025-05-31
- validation / early stopping: 2025-06-01..2025-06-30
- development test: 2025-07-01..2025-08-31
- frozen pre-holdout check: 2025-09-01..2025-09-30
- final holdout: 2025-10-01..2025-12-31 SEALED

ただし、最初からROIで大量の閾値探索をしない。まず確率品質（logloss/Brier/calibration）と特徴量の増分価値を確認してから、固定的な小さなpolicy familyで購入評価する。

## モデル案

r4第一候補は二段構成。

### Model A: race outcome probability

- LightGBM / CatBoost相当の小容量モデル
- 6艇×選手履歴 + 当日展示 + 相対差 + race features
- 1着→2着→3着のconditional model、または120通りrace softmax
- 選手登録番号そのものは直接投入せず、履歴統計へ変換

### Model B: market residual / value selector

Model Aの確率とmarket probabilityの差を使うが、既存r1/r2の単純market correction再現にはしない。

選手固有の「展示反応が市場に織り込まれていない時」を狙う。

例:

- `model_p / market_p`
- 選手本人比展示改善
- player×course反応
- lane1 weakness
- market concentration

を使い、最終的にCORE BUY候補を選ぶ。
