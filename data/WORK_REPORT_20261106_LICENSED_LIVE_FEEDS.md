### 2.1 公式ルートで確認すべきこと

公式ポリシーは権利者の許諾を一般に与えるものではなく、大量アクセス等も制限している [S1]。これは個々の事実データの法的評価を一律に断定する説明ではないが、今回求める「許諾が明確なクラウド配信」の根拠としては足りない。

公式の説明では、オッズは画面の更新操作で取得し、表示される更新時刻を参照する。水面気象は原則として直近レースの天候である [S2]。したがって「ページを受信した時刻＝オッズ更新時刻＝気象観測時刻」にはできない。展示・ST・気象・オッズを同一時刻の測定値とみなさない。

問い合わせ先は公式案内にある**BOAT RACEオフィシャルWEB窓口 03-5539-8696、10:00〜18:00**。正規のデータ利用/配信契約担当への取り次ぎを求める。ご意見フォームは質問への返信を約束していないため、契約申請窓口として確定扱いしない [S3]。

関連する技術的照会先の手掛かりとして、JLCは公式サイト・場HPの運営と競技データ取扱いを公表している [S10]。ただし、これは外部開発者向けデータAPI販売の証拠ではない。一般電話には商談等を控える旨の案内があるため、一般窓口へ営業問い合わせを送る手順は推奨しない。まず公式窓口で正規の配信担当を確認する。

### 2.3 BoatraceCSVの不足点

- `tkz`、`stt`、`sui`、`od3` の4系統を同じレースIDで結合する必要がある。1ファイルの取得成功だけでは6艇展示＋全オッズの完備にならない。
- 共通の「取得日時」は収集側の時刻。`sui` は別に「気象観測時刻」を持つが、他系統に同等の上流観測時刻があるとは公開スキーマから確認できない [S7]。
- `取得日時`をそのまま全項目の `observed_at` に入れ、キャッシュを読んだ現在時刻で更新してはいけない。収集者が上流の現在データをいつ確認したか、その意味と記録方法を確認する必要がある。
- 120欄の存在と120有効値は異なる。`0.0` は未投票や発売対象外にも使われる [S7]。現在のWorkerは120通りすべての正の有限数値を必要とするため、0を推定値や1倍に変換して完備扱いしない。
- 5分周期と取得可能時間帯の仕様だけでT-8成功率を計算しない。収集処理、commit、公開キャッシュまでの遅延も未測定。
- MIT表記は確認したが、それのみで上流の再許諾権限、ライブ原データの公開再配信、出典表示条件、キャッシュ保存期間、派生予想配信の条件まで確認済みとはしない。

## 6. 許諾後に行うライブ試験の手順（未実行・未予約）

### 取得条件と時刻

初めに1レースで疎通し、その後、開催場・時間帯の異なるレース集合を**取得前に固定**して前向き計測する。成功したレースだけを後から選ばない。

- T-8で初回。失敗したレースだけT-5に1回。HTTP内部で無制限の再試行・ポーリングを加えない。429、アクセス拒否、利用停止の応答は尊重し、提供元が要求する待機期間があればT-5より優先する。
- Cron実起動、各endpointのrequest開始、body受信完了を別記録。実際の締切前に受信・検証まで完了したかを確認し、T-8へ時刻を遡って記録しない。
- 展示/ST/気象/オッズそれぞれの上流観測・更新時刻、収集者の観測時刻、配信/公開時刻、Worker受信時刻を、得られる範囲と意味を明示して区別する。
- 展示の物理的計測時刻と「配信元が現在のデータとして確認した時刻」も区別。既存の `observed_at` は後者の証拠を必要とし、キャッシュ配信時刻で代用しない。
- 現行2分以内の鮮度ゲートを緩和しない。上流時刻が不明なら完備として扱わない。気象が直近レースの観測値ならその日時と対象を残す。
- レースID・6艇の枠/登録番号・進入コース・展示タイム/ST・気象・120組番を照合。欠場/中止/締切変更は別理由で記録し、全120組番を推定生成しない。
- `UNAVAILABLE` とモデル評価後の `SKIP` を分離。推奨と予想完了時刻の偽装をしない。

### 計測指標の定義

| 指標 | 定義 |
| --- | --- |
| T-8試行率 | 事前登録した対象Rのうち、実際にT-8段階の取得を開始できたR数。Cron遅延・未実行も別集計 |
| T-8完備成功率 | 初回段階で許諾・同一性・6艇/ST/気象・120オッズ・時刻・締切前完了を満たしたR / 初回対象R |
| T-5救済率 | T-8失敗Rのうち、T-5再試行で初めて完備したR / 再試行対象R |
| 最終完備率 | T-8またはT-5で完備したR / 事前登録対象R。取得不能を分母から消さない |
| 完備率の内訳 | 展示6艇、ST6艇、気象、120有効オッズ、時刻証跡を各々測定。組合せ全体の完備率も併記 |
| 観測から締切まで | 締切 D − ソース観測 O（各系統別、秒） |
| 受信から締切まで | D − body受信完了 R。OとRを混ぜない |
| データ年齢 | R − O（各系統別）。不明/不正/未来時刻は別分類 |
| HTTP応答時間 | monotonic clockでrequest開始〜body受信完了。各系統別p50/p95、標本数、timeout数、失敗応答も報告 |
| 取消・変更 | 事前に定義した扱いを保ち、取消・締切変更と通信欠損を分ける。後から除外して成功率を上げない |
