# BOAT AI v0.18.29：2台目の限定遠隔操作（2026-11-08）

## 目標と境界

ユーザーの最終目標は、AIが2台目Androidを使ってデータ取得や購入**準備**を進め、1台目で結果を確認すること。

今回の第1段階は **BOAT AIアプリ内部の再取得指示（REFRESH_NOW）だけ**を、既存の認証済みCloudflare通信経由で流す。Androidの他アプリへのタップ・画面共有・購入・投票確定・ログイン資格情報取得はなし。AndroidのAccessibility APIは要求しない。

## 操作フロー

1. 1台目Android v0.18.29の設定で、2台目と同じCloudflare共有キーを保存（Android Keystoreによる端末内暗号化、ユーザーはチャットに値を送らない）。1台目の「常時取得モード」はOFF。
2. 1台目の「予想」または「設定」に「2台目に今すぐ再取得を指示」ボタンが表示される。直近の端末監視が `ACTIVE` の場合だけ押せる。
3. Workerは認証・固定アクション・最新端末の活動時刻・発行頻度を検証し、D1に1件投入。3分後には失効し、端末ID・トークンは外へ返さない。
4. 2台目は常時取得画面が**前面表示中**に、既存60秒ループで新しいコマンドをポーリング。重複排除して既存の `loadDate(today)` を呼ぶ。ACKは「受信・開始」であり取得成功ではない。
5. 既存のheartbeat監視で最終データ時刻・件数を確認。取得先の欠損があれば従来通り警告、AI予想の `BUY/SKIP` に使わない。

## セキュリティと制限

- 認証未設定・異常形式・未登録端末を拒否。固定操作1種類だけ。D1 unique indexで多重指示を防止。
- リモートキーの再使用は段階1用の選択。高権限の汎用端末遠隔操作を開始する際は権限を分離し、操作承認・失効・詳細監査を再設計する。
- AIはチャットから私物端末へ直接アクセスできない。発行経路は現在1台目の明示ボタンのみ。AIが指示を出すための安全な連携は別工程であり、今は未実装。
- 実際のテレボート自動投票は本工程の対象外。公式利用約定の制限に抵触しないことを先に確認する。ユーザーが最終投票を行う。
- アプリ停止中のバックグラウンド操作、アクセシビリティでの他アプリ操作、画面共有、常駐プッシュ通知は未実装。

## 検証

- Cloud worker `npm test`：固定操作の許可リスト、不正認証、入力検証、登録済み/未登録端末、期限切れ、重複排除、連続指示制限、D1 migrationの制約。
- Android単体テスト：固定操作、空指示、期限切れ、投票指示拒否。
- GitHub ActionsでAndroid debug CI、Cloudflare本番への自動デプロイ、署名済みAPKのビルド・公開を確認すること。
